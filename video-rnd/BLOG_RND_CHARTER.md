## 1. 업무 3가지와 R&R (RACI)

R = 실제로 하는 쪽 · A = 결과 책임 · C = 의견을 주는 쪽 · I = 결과를 받아 보는 쪽

| # | 업무 (대표 지시) | R | A | C | I | 산출물 | 주기 |
|---|---|---|---|---|---|---|---|
| **1** | **판매형 블로그 탐색 · 잘 나오는 구성 학습** | ① 자비스 **자동 스터디**(Claude 1회 + 웹 검색) ② Antigravity **심층 스터디** | Antigravity | Claude Desktop | 대표 | 관찰·출처가 붙은 스터디 문서(`blog/STUDY-NNN.md`) + `blog/playbook.json` 대기열에 가설 등록 | 자비스 매주 자동 / Antigravity 격주 |
| **2** | **내 블로그에 적용 · 클릭되는 표지(제품 포함)** | 자비스 (상품 글 작성기 + `blog_rnd` 변형 배정) | 자비스 | Antigravity (표지 새 시안·스펙), Claude Desktop (고지·진실성 기준) | 대표 | 네이버 블로그 글, 글마다 변형 ID · 글 전용 쿠팡 채널 ID(`nb-…`) | 상품 글이 나올 때마다 |
| **3** | **잘 되는/안 되는 이유 분석 · 묻지 않고 자동 개선** | 자비스 (매일 측정 · 미리 정한 규칙으로 자동 승격/폐기) | 자비스 (규칙 안에서) | Antigravity (원인 분석 = 다음 스터디), Claude Desktop (KPI 해석 · 규칙 변경 제안) | 대표 (실적 탭 · `results.json` — **묻지 않음**) | `blog/results.json` 결정 기록, `improvements.ts` 항목 | 매일 측정, 결론 날 때마다 결정 |

### 역할별 한 줄

- **Antigravity (영상·콘텐츠 R&D):** 판매형 블로그의 제목·구성·첫 문단·표지를 연구해 **검증 가능한 가설**로 만들어 `playbook.json`에 올린다. 결과(`results.json`)를 보고 왜 이겼/졌는지 원인을 다음 스터디에 쓴다. 새 표지 디자인은 시안·스펙으로 내고, 자비스 쪽 코드 반영은 요청한다 (자비스 코드는 비공개).
- **Claude Desktop (마케팅·플랫폼·경영관리):** B 라인 KPI·판정 규칙의 주인. 진실성·대가성 고지 기준을 지키는지 본다. 조회수 데이터 확보(B-DATA-1)를 조사한다. 판정 규칙을 바꿀 때는 대표에게 올린다.
- **자비스 (메인 PC):** 실행·측정·자동 결정. 글마다 변형을 배정하고, 매일 실측해 규칙대로 **묻지 않고** 승격·폐기한다. 매주 스터디를 자동으로 하고, 결과를 이 저장소에 공개한다.
- **대표:** 결과를 받아 본다. 아래 §3의 '잠긴 것'을 바꿀 때만 결정한다.

## 2. 자동 개선 순환 — 대표에게 묻지 않고 도는 부분

```text
 [Antigravity 심층 스터디]   [자비스 주간 자동 스터디]
            │  가설(변수 1개만)            │
            ▼                             ▼
        video-rnd/blog/playbook.json  ──►  자비스 대기열 (검사 통과한 것만)
                                              │
       상품 글마다 ◄─── 챔피언(지금 기본) / 도전안(가설 1개) 번갈아 배정
                                              │  글 전용 쿠팡 채널 ID nb-<작업id>
                                              ▼
                       네이버 블로그 '찰스 추천템' 공개 발행
                                              │
                              매일: 쿠팡 파트너스 리포트(최근 30일) 실측
                                              │
                ┌─────────── 판정 규칙(아래 표) ───────────┐
                ▼                                          ▼
       도전안 승격 → 새 기본(챔피언)              도전안 폐기 → 기본 그대로
                └──────────► 다음 가설 시작 ◄──────────────┘
                                              │
                         video-rnd/blog/results.json 자동 갱신 (R&D팀이 봄)
```

### 판정 규칙 (미리 정해 두고 그대로 결정 — 대표 확인 없음)

| 항목 | 값 |
|---|---|
| 비교 단위 | 같은 기간에 번갈아 쓴 챔피언 글 vs 도전안 글 |
| 최소 표본 | 변형마다 **4편 이상**, 발행 후 **7일 이상** 지난 글만 |
| 지표 | 글당 **조회수**(데이터가 생기면) → 없으면 글당 **쿠팡 링크 클릭**(글 전용 채널 ID, 실측) |
| 승격 | 도전안 평균 ≥ 챔피언 평균 × **1.2** |
| 폐기 | 도전안 평균 ≤ 챔피언 평균 × **0.9** |
| 보류 | 두 변형 클릭 합이 **10 미만**이면 우연일 수 있어 판정하지 않음 |
| 종료 | 변형마다 **8편**이 넘도록 결론이 없으면 '차이 없음'으로 종료, 챔피언 유지 |
| 한 번에 | 도전안은 **1개**, 바꾸는 변수도 **1개** |

> 규칙 숫자를 바꾸는 것은 Claude Desktop이 제안하고 대표가 결정한다 (AGENDA로 올림).

## 3. 자동으로 바꿀 수 있는 것 / 없는 것

**자동으로 바꿀 수 있는 변수 (화이트리스트):**

| 변수 | 뜻 | 값 |
|---|---|---|
| `title` | 제목 공식 | 필자에게 주는 지시문 (30~400자) |
| `structure` | 글 구성 순서 | 지시문 |
| `hook` | 첫 문단 | 지시문 |
| `cover` | 표지 배치 | `classic` (제품 사진 + 제목 2줄 + 가격) · `hero_keyword` (제품 크게 + 큰 고민·용도 글씨 + 가격) — 새 배치는 Antigravity 시안 → 자비스 코드 반영 후 추가 |

**잠긴 것 — 자동 개선이 절대 못 바꿈 (가설에 들어 있으면 자비스가 받지 않음):**

1. 광고·수수료 고지는 글 맨 위·맨 아래 (코드가 붙임)
2. 숫자는 상품 정보(판매 페이지에서 확인한 값)에 있는 것만 — 코드가 검사
3. 써 본 척하는 말 금지 — 내돈내산 · 써 보니 · 먹어 보니 · 솔직 후기 등 (FIX-001과 같은 기준)
4. 근거 없는 1위 · 최저가 · 별점 · 후기 수 · '오늘만'·'마감 임박' 재촉 금지
5. 구매 링크는 2곳만
6. 남의 블로그 글·사진을 옮기지 않음 (구조만 참고)
7. 크레딧이 드는 변경(AI 그림 장수), 발행 횟수, 카테고리 — **대표 결정**

## 5. 가설 올리는 법 — `blog/playbook.json`

자비스는 하루 한 번 이 파일을 읽어 **처음 보는 id**의 가설만 대기열 뒤에 붙인다 (검사 통과한 것만, 대기열 최대 6개). 챔피언은 실측 승격으로만 바뀐다 — 이 파일로 덮어쓰지 않는다.

```json
{
  "queue": [
    {"id": "A1", "name": "20자 안팎 이름", "var": "title|structure|hook|cover",
     "value": "필자에게 줄 지시문 30~400자 (cover면 classic|hero_keyword)",
     "why": "근거 — 관찰·출처·우리 숫자 (150자 안팎)", "by": "Antigravity"}
  ],
  "retire": ["대기열에서 뺄 id"]
}
```

- id: 영문 대문자 1~3자 + 숫자 (Antigravity `A…`, Claude Desktop `CD…`, 자비스 스터디 `S…`, 초기 가설 `T…`)
- 한 가설은 **변수 1개**만. 잠긴 것(§3)을 건드리는 말이 있으면 버려진다.
