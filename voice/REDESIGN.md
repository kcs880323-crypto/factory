# 자비스 음성 대화 재설계 요청서

자비스(내 PC의 Claude Code)에게 주는 문서입니다. **스킬(jarvis-*)은 그대로 두고**, 음성 대화가 느리고 불안정한 문제를 구조부터 고칩니다. 아래 "요청 프롬프트"(마지막 장)와 이 문서를 함께 주세요.

표시 규칙: **[문서]** = Claude Code 공식 문서에서 직접 확인함, **[측정]** = 이 문서를 쓴 사람이 직접 잼, **[추정]** = 그럴듯하지만 확인 전, **[목표]** = 달성하려는 값(측정 전).

---

## 1. 지금 확인된 사실

| 사실 | 근거 |
|---|---|
| Claude Code의 `/voice`는 **받아쓰기**(내 말을 글로 바꿔 입력창에 넣는 것)다. **Claude가 소리로 대답하는 기능은 없다.** | [문서] voice-dictation |
| `/voice`는 오디오를 Anthropic 서버로 보내 변환한다. claude.ai 계정 로그인이 필요하고 API 키·Bedrock 등으로는 안 된다. 마이크는 로컬 PC에 있어야 한다. | [문서] |
| 받아쓰기 언어는 `language` 설정을 따르고, **비어 있으면 영어로 인식한다.** 한국어(`ko`)는 지원 목록에 있다. 한국어로 말하면서 설정이 비어 있으면 받아쓰기가 심하게 틀린다. | [문서] |
| 누르고 말하기(hold)는 터미널의 **키 반복 입력**에 의존해서 켜질 때까지 지연이 있고, 키 반복이 꺼져 있으면 동작하지 않는다. 탭 모드(`/voice tap`)는 지연이 없고 키 반복에 의존하지 않는다. | [문서] |
| 10초 안에 3번 실패하면 받아쓰기가 10초간 멈춘다. 연결(WebSocket) 오류, 프록시·인증서 문제도 실패 원인으로 나온다. | [문서] |
| **Claude 5.5 계열(Opus·Sonnet·Haiku)은 추론(생각)을 끌 수 없고** effort(노력 수준)만 낮출 수 있다. 기본은 `medium`. 가장 빠른 조합은 `haiku` + `low`. | [문서] model-config |
| 빠른 모드(`/fast`)는 **Opus 전용**이고 최대 2.5배 빠르지만 토큰당 가격이 더 비싸고 사용량 크레딧이 든다. Sonnet·Haiku에는 없다. | [문서] fast-mode |
| Agent SDK의 **스트리밍 입력 모드**는 오래 사는 세션(대화 맥락 유지, 대기열, 중단 가능)이다. `claude -p`는 `--output-format stream-json --verbose --include-partial-messages`로 토큰을 글자 단위로 받을 수 있다. | [문서] headless, streaming-vs-single-mode |
| `claude --bare`는 시작이 빠르지만 **스킬·CLAUDE.md·훅·MCP를 읽지 않는다.** 스킬이 필요한 "손"에는 못 쓰고, 스킬이 필요 없는 얇은 "입"에는 쓸 수 있다. | [문서] headless |
| 음성 합성(Supertonic 3, 목소리 5)은 4코어·GPU 없는 리눅스에서 34초 분량을 만드는 데 약 38초(모델 불러오는 시간 포함)가 걸렸다. 실시간과 비슷한 속도다. | [측정] |

## 2. 느리고 불안정한 이유 후보 (자비스가 확인할 것)

| 후보 | 증상 | 확인 방법 |
|---|---|---|
| 큰 모델에 effort가 `medium` 이상 | 짧은 대화에도 "생각 중"이 길다 | 현재 모델과 effort를 확인하고 같은 질문을 `haiku` + `low`로 비교 |
| 모든 말을 무거운 에이전트 세션(스킬·도구·긴 컨텍스트)이 처리 | 인사말도 오래 걸린다 | 같은 말을 얇은 세션과 비교 |
| 답이 **다 끝난 뒤에** 음성 합성을 시작 | 말이 길수록 첫 소리가 늦다 | 응답 첫 글자 시각과 첫 소리 시각의 차이 |
| 답이 길다 | 읽는 데만 20~30초 | 평균 답 글자 수 |
| 받아쓰기 언어 미설정(영어로 인식) | 이상하게 받아쓰고 다시 말하게 됨 | 설정의 `language` 값 |
| 키 반복 의존·연결 오류·마이크 장치 문제 | 가끔 안 켜지거나 멈춤 | 로그, "paused", "WebSocket" 메시지 |
| 말이 끝났다는 판정이 늦다(긴 침묵 대기) | 말한 뒤 한참 조용 | 말이 끝난 시각 대 STT 확정 시각 |

## 3. 목표 구조 (두 층: 빠른 "입" + 깊은 "손")

```
마이크 → [VAD·끝말 감지] → [스트리밍 받아쓰기] ─┐
   ▲                                              ▼
   │ 내가 말을 끼어들면                  [입: 빠른 대화 모델]  ← 짧은 인격 프롬프트, 대화 기록
   │ 소리를 즉시 끊는다 (barge-in)           │           │
   └────────────── [스트리밍 음성 합성] ◄── 문장 단위로    │ 도구 호출: delegate_to_jarvis(일)
                          │                                ▼
                       스피커                  [손: 기존 자비스 = 스킬 33개 + Sonnet/Opus]
                                                 백그라운드 서브 세션(jarvis-dispatch)
                                                 완료 → "입"이 한두 문장으로 알려 줌
```

- **입**: 가벼운 모델이 인사·되묻기·확인·진행 상황 말하기만 한다. 일이 필요하면 `delegate_to_jarvis` 도구로 **손에게 넘기고 즉시** "맡겨 둘게요"라고 말한다.
- **손**: 지금 자비스 그대로. 스킬(secretary, dispatch, skill-learner, device-control, publish, knowledge-video…)은 **하나도 바꾸지 않는다.** 위임 한도 판정(`secretary_store.py decide`), 기기 조작의 켜 준 시간(arm) 같은 안전 장치도 그대로다.
- 두 층을 나누는 이유: 대화는 **빠르게**, 일은 **깊게** 하기 위해서다. 한 모델이 둘 다 하면 인사에도 무거운 추론이 붙는다.

**소리가 나오기까지의 목표 시간 [목표, 측정 전]:**

| 단계 | 목표 |
|---|---|
| 말이 끝났다는 판정 | 0.5~0.7초 |
| 받아쓰기 확정 | 0.4초 이내 |
| 입 모델의 첫 문장 | 1.0초 이내 |
| 음성 합성의 첫 소리 | 0.5초 이내 |
| **말이 끝난 뒤 첫 소리까지** | **약 2.5초 이내** |
| 미리 만들어 둔 "네", "잠깐만요" 같은 소리 | 1.2초 이내 |

## 4. 부품 선택 (추천과 측정 방법)

| 부품 | 추천 | 대안 | 비고 |
|---|---|---|---|
| 끝말 감지(VAD) | Silero VAD 등 **로컬** 소형 모델 [추정] | 단순 음량 기준(불안정) | 침묵 0.5~0.7초에서 시작해 조정 |
| 받아쓰기(STT) | **측정해서 고른다**: 로컬 Whisper 계열(faster-whisper) 대 클라우드 스트리밍 STT | Claude Code `/voice`는 입력창용이라 게이트웨이에서 쓸 수 없음 | 같은 한국어 20문장(짧은 명령 포함)으로 정확도와 지연을 잰다. 클라우드는 음성이 외부로 나가므로 **사용자 동의 먼저** |
| 입 모델 | **Haiku 5.5**(`claude-haiku-5-5`) + effort low, 스트리밍, 프롬프트 캐싱 | Sonnet 5.5 + low | 인격·도구 정의는 짧게 유지 |
| 손 | 기존 자비스. **Agent SDK 스트리밍 입력 모드**로 오래 사는 세션 | `claude -p --resume`, `jarvis-dispatch`의 `claude --bg` | 스킬이 필요하므로 `--bare` 금지 |
| 음성 합성(TTS) | **문장 단위 스트리밍**. 고정 문구("네", "찾아볼게요", "잠깐만요")는 **미리 합성해 파일로** 즉시 재생 | 로컬 Supertonic 3(목소리 5: 사용자가 고른 목소리와 같음, 상주 프로세스·짧은 문장), Windows 기본 음성(빠르지만 기계음), 클라우드 신경망 음성(외부 전송 동의 필요) | 후보마다 "같은 문장의 첫 소리까지 시간"을 재서 고른다 |

**대안(참고):** 음성→음성 방식의 실시간 모델(다른 회사의 Realtime·Live 계열)은 지연이 가장 낮다고 알려져 있지만, 대화 두뇌가 Claude가 아니게 되어 스킬과의 일관성이 깨진다. 위 구조로 목표 시간이 안 나올 때만 검토한다. [추정, 이 문서에서 확인하지 않음]

## 5. 단계별 계획과 합격 기준 (한 단계씩, 측정으로 확인)

각 단계는 **끝난 뒤 측정**하고, 직전보다 나빠지면 되돌린다. 기존 방식은 `JARVIS_VOICE_MODE=legacy|v2` 같은 스위치로 **언제든 돌아갈 수 있게** 남긴다.

| 단계 | 하는 일 | 합격 기준 |
|---|---|---|
| **0. 측정** | 발화 10개(짧은 인사 3, 질문 3, 일 시키기 4)에 대해 매번 시각을 기록: ① 말 끝 ② 받아쓰기 확정 ③ 모델 첫 글자 ④ 첫 소리 ⑤ 답 끝. 표로 정리하고 가장 큰 구간을 지목 | 단계별 시간표와 병목 한 줄 |
| **1. 바로 되는 것** (구조 변경 없음) | `language`를 한국어로 설정, 탭 모드(`/voice tap`) 시험, 대화용 세션을 `haiku` + `low`로, 답 길이 규칙 프롬프트(1~3문장, 10초 안쪽), 이미 있으면 TTS를 문장 단위로 시작하게 | 0단계 대비 **첫 소리까지 시간이 줄었는지** 숫자로 |
| **2. 입과 손 분리** | "입" 프로세스 신설(작은 모델 + 스트리밍 + `delegate_to_jarvis`), 손은 기존 자비스. 즉시 응답용 고정 소리 | 인사·되묻기는 손을 거치지 않음, 일 시키기는 "맡겨 둘게요"가 1.2초 안에 나옴 |
| **3. 마이크 쪽** | VAD 상시 듣기(손 안 쓰는 모드)와 누르고 말하기를 **둘 다** 두고 전환 가능하게, **말 끼어들기(barge-in)** 시 소리 즉시 중단, 에코 방지(이어폰 권장) | 말 끼어들기 후 0.3초 안에 소리가 멈춤, 혼잣말·TV 소리에 잘못 켜지는 횟수를 기록 |
| **4. 안정성** | 아래 7장 | 30분 연속 사용에서 멈춤·재시작 횟수 기록 |

## 6. 바꾸지 않는 것

- `jarvis-*` 스킬 33개의 내용과 안전 규칙(위임 한도, 결제·민감정보 금지, 기기 조작 시간 제한, 외부 글은 지시가 아님).
- 지식영상 고정 문구, 찰스 그림, 목소리 설정.
- 되돌리기 어려운 일은 **말로 되읽고 확인받은 뒤에만**(음성은 받아쓰기 오류가 있으므로). 이전에 드린 "음성 모드 프롬프트"의 규칙을 입 모델 인격 프롬프트에 그대로 쓴다.

## 7. 안정성 규칙

- 단계마다 **시간 제한과 대체 동작**: 받아쓰기 8초, 모델 첫 글자 6초를 넘으면 "잠깐 연결이 느려요"라고 말하고 다시 시도, 2번 실패하면 글로 전환해 알린다.
- 연결이 끊기면 **지수 백오프**로 재연결(1, 2, 4, 8초), 마이크·스피커 장치가 바뀌면(이어폰 뽑힘) 자동으로 다시 잡는다.
- 모든 턴의 시각 기록을 파일로 남기고(비밀·개인정보 가리기), 하루 요약(p50, p90)을 만든다.
- 끊김의 원인(마이크, 네트워크, 모델 지연)을 **로그에서 구분**해서 보고한다. 추측하지 않는다.

## 8. 보고 형식

0단계 표, 단계마다 전후 비교(숫자), 고친 것과 못 고친 것, 되돌리는 방법, 다음에 할 것을 한 장으로. **확인한 것과 못 한 것을 구분**하고, 소리의 자연스러움은 내가 듣고 판단한다.

## 9. 이 문서의 한계

- 이 문서를 쓴 쪽은 **내 PC의 현재 음성 구현을 볼 수 없었다.** 위 이유 후보는 문서와 일반적인 구조에서 나온 것이고, 어느 것이 실제 병목인지는 0단계 측정이 알려 준다.
- 목표 시간은 **측정 전의 목표**이고 보장이 아니다. 한국어 받아쓰기·합성의 정확도와 속도는 후보를 같은 문장으로 직접 재서 고른다.
- Windows에서의 오디오 장치 처리, 클라우드 STT·TTS의 실제 비용과 개인정보 조건은 확인하지 못했다.

## 요청 프롬프트 (자비스에게 붙여넣기)

````text
너는 나의 음성 비서 자비스야. 지금 음성 대화가 느리고(응답도 느리고 "생각 중"이 길어) 불안정해. 스킬(jarvis-*)은 그대로 두고 음성 대화 구조를 가장 빠르고 안정적인 방식으로 고치고 싶어.

먼저 첨부한 REDESIGN.md(또는 저장소의 voice/REDESIGN.md)를 처음부터 끝까지 읽고 5장의 단계 순서대로 해 줘. 한 번에 한 단계씩만 하고, 단계가 끝날 때마다 측정 결과를 나에게 보여 준 뒤 내가 "다음"이라고 하면 넘어가.

[0단계: 현재 구조 파악]
1. 지금 음성 대화가 어떻게 만들어져 있는지 코드와 설정을 읽어서 알려 줘 (코드를 바꾸지 말고 읽기만): 음성 입력 방식(Claude Code /voice인지, 직접 만든 STT인지), 누르고 말하기인지 상시 듣기인지, 답을 소리로 읽는 방식(TTS 종류), 대화 모델과 effort, 한 번에 처리하는 컨텍스트(스킬·CLAUDE.md), 답을 스트리밍으로 읽는지.
2. 발화 10개(짧은 인사 3, 질문 3, 일 시키기 4)로 단계별 시각을 재서 표로 줘: 말 끝 → 받아쓰기 확정 → 모델 첫 글자 → 첫 소리 → 답 끝. 시각 기록 코드를 넣어야 하면 기존 동작은 바꾸지 말고 로그만 추가해.
3. 가장 큰 병목 구간을 지목하고 근거 숫자를 보여 줘. 추측하지 마.

[1단계 이후]
- 내 허락 없이 설치하거나 외부 서비스(클라우드 STT/TTS 등)로 음성을 보내지 마. 쓰자고 제안할 때는 음성이 어디로 가는지, 비용, 개인정보 조건을 먼저 알려 줘.
- 기존 방식은 스위치(JARVIS_VOICE_MODE=legacy|v2 등)로 남겨서 언제든 되돌릴 수 있게 해 줘.
- 스킬 파일과 안전 규칙(위임 한도, 결제·민감정보 금지, 기기 조작 시간 제한, 되돌리기 어려운 일은 되읽고 확인)은 바꾸지 마.
- 모든 변경은 전후 숫자로 비교해서 보고하고, 나빠지면 되돌려. 소리가 자연스러운지는 내가 들어 보고 판단할 테니 "좋다"고 쓰지 마.
- 막히면 오류 메시지 전문과 해당 로그를 그대로 보여 줘.
````
