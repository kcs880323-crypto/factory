# 지식영상 생성: 찰스의 30초 지식 영상 만들기

사용자가 **"지식영상 생성"**이라고 말하면 이 절차대로 영상 한 편을 만듭니다. 주제를 같이 말하면(예: "지식영상 생성: 무지개") 그 주제로, 말하지 않으면 **내가 고릅니다.** 한국어 나레이션과 자막, 1920×1080, 30fps, 설명이 한 장면씩 자라는 본편에 **찰스의 고정 오프닝과 엔딩**이 앞뒤로 붙고, 전체 길이는 **35~45초**(본편 낭독 25초 안팎 + 오프닝·엔딩 약 11초)입니다. 첫 예시는 「꿀벌의 8자 춤」(30초, 오프닝·엔딩 도입 전)과 「문어의 심장은 세 개」(44초, 찰스 포함)입니다.

## 찰스 (채널 캐릭터)와 고정 문구

채널 이름은 **찰스**, 캐릭터 **찰스**는 **사용자가 직접 만든 그림**입니다: 남색 베레모(졸업모 술 장식)와 둥근 안경, 남색 스카프와 망토를 두른 하얀 오리 박사로, **빛나는 별이 든 유리병(= 오늘의 지식)**을 들고 있습니다. 시그니처 색은 남색(지성) + 옐로(에너지) + 크림 화이트. 포즈 4가지가 `assets/charles/`에 있습니다 (`charles-sheet.png`로 한눈에). 문구는 **사용자가 정한 것이라 한 글자도 바꾸지 않는다.**

| 포즈 (`pose-*.png`) | 모습 | 쓰는 곳 |
|---|---|---|
| `idea` | 손가락을 들고 머리 위 전구가 켜짐, 유리병을 듦 | 오프닝 "30초만 주면, 지식 하나 드릴게요." / 엔딩 "알아두면 언젠가 쓴다!" |
| `wave` | 한 손을 흔들고 유리병을 듦 | 오프닝 "찰스입니다!" / 엔딩 "찰스였습니다!" |
| `hug` | 가슴에 손을 얹고 옆을 향함 | 엔딩 "오늘의 지식공유가 유익했다면" |
| `like` | 엄지 척 + 윙크, 다른 손으로 가리킴, 유리병은 발치 | 엔딩 "좋아요와 구독," |

| 구간 | 문구 | 화면 |
|---|---|---|
| 오프닝 | **"30초만 주면, 지식 하나 드릴게요. 찰스입니다!"** | 노란 바탕에 `idea` 찰스, "30초" → "지식 하나"(전구가 반짝) → `wave`로 바뀌며 "찰스입니다!" 판이 낭독에 맞춰 등장 |
| 엔딩 | **"알아두면 언젠가 쓴다! 오늘의 지식공유가 유익했다면 좋아요와 구독, 찰스였습니다!"** | `idea` "알아두면 언젠가 쓴다!" → `hug` → `like`로 바뀌며 점선 자리에서 "좋아요"(엄지) → "구독"(종 울림) 버튼이 채워짐 → `wave` "찰스였습니다!"를 2초 이상 유지 |

- **말할 때의 움직임:** 그림이 입 모양 한 가지로 고정이라 입은 움직이지 않는다. 대신 **낭독 소리 크기(프레임당 RMS, `charles.mouth_track`)에 맞춰 몸이 늘었다 줄고 살짝 흔들리며**, 포즈는 낭독 구절에 맞춰 바뀐다. 입 모양까지 움직이게 하려면 사용자가 **입 벌린/닫은 그림**을 따로 줘야 한다.
- 오프닝·엔딩 장면은 `scripts/charles.py`의 `write_scenes`가 만든다 (포즈 PNG를 프로젝트 `assets/charles/`로 복사). 주제마다 새로 그리지 않는다. 본편 색과 상관없이 찰스 그림의 노란 바탕(`#FCE06B`)과 남색 글자를 쓴다.
- 오프닝·엔딩이 고정이므로 **본편 낭독은 공백·문장부호 제외 약 125~160자**로 쓴다 (기본 음성 Supertonic 3 목소리 5, 속도 1.2, 클립 앞뒤 무음 제거 상태. 오프닝·엔딩 낭독이 약 12초이고 줄 사이 간격이 더해진다. 직접 재 보니 **115자 → 전체 36초, 135자 → 39초, 149자 → 41초, 168자 → 45초(낭독이 42.3초에 끝나 상한 43초에 거의 닿음)**). 40초 안에 끝내고 싶으면 본편을 145자 안팎으로 줄인다.
- **찰스 그림을 바꿔 달라고 하면:** 새 그림(단색 배경 위의 PNG/JPG, 포즈마다 한 장)을 받아 `assets/charles/original/`에 두고 `scripts/charles_cutout.py`로 배경을 지운 `pose-*.png`와 `charles.json`(발 기준점)을 다시 만든다 (Pillow 필요: 가상환경에 `pip install pillow`는 사용자에게 알리고). 포즈 이름 `idea` `wave` `hug` `like`를 그대로 쓰고, `idea`에는 전구 위치(`--mark idea.bulb x,y`)를 준다. 만든 뒤 `snapshot`으로 각 포즈가 잘리거나 어긋나지 않았는지 본다. 사용자가 준 그림은 사용자 것이므로 원본을 지우거나 덮어쓰지 않는다.

이 스킬은 **HyperFrames 플러그인**(`jarvis-hyperframes` 스킬, `install.sh --with-video-skills`)을 쓴다. 영상 제작 규칙은 그 플러그인의 `/hyperframes:hyperframes`가 가진 것이 우선한다.

## 1. 주제 정하기

1. 사용자가 준 주제가 있으면 그것. 없으면 무작위로 고른다. **`knowledge-videos/ledger.json`**(없으면 만든다)에 이미 만든 주제가 있으면 겹치지 않게 한다.
2. 좋은 주제: **한 가지 원리를 한 문장으로 말할 수 있고**, 그림으로 단계마다 보여 줄 수 있는 것 (자연, 우주, 몸, 날씨, 동물, 역사 속 발견, 일상 속 과학).
3. 피할 것: 의학·법률·투자 조언, 논란이 큰 정치·사회 쟁점, 실존 인물 비방, 불확실한 통계, 특정 상표·캐릭터가 중심인 주제.

## 2. 사실 확인 (건너뛰지 않는다)

- **확실히 아는 사실과 출처로 확인한 사실만** 대본에 쓴다. 이름, 연도, 숫자는 특히 확인한다.
- 웹 검색이 가능하면 핵심 주장마다 신뢰할 만한 출처 하나 이상을 찾아 **`SOURCES.md`**(주장 → 출처 주소)에 적는다. 가능하지 않으면 "출처는 확인하지 못했다"고 보고에 쓴다.
- 확인되지 않는 부분은 빼거나 "~로 알려져 있다"로 쓴다. 그럴듯하게 지어내지 않는다.

## 3. 대본(본편): 5줄, 절(clause) 12개 안팎

| 줄 | 역할 | 예(꿀벌) |
|---|---|---|
| 1 | 훅: 질문 한 개 | 벌집 안은 깜깜합니다. 꿀이 있는 곳을 어떻게 알려 줄까요? |
| 2 | 정답 | 정답은 춤입니다. |
| 3 | 원리 (핵심 도표가 자란다) | 직선 구간의 방향이 태양 기준 방향입니다. |
| 4 | 한 가지 더 | 흔드는 시간이 길수록 멉니다. |
| 5 | 마무리: 한 문장 + 출처 있는 사실 | 이 발견으로 카를 폰 프리슈는 1973년 노벨상을 받았습니다. |

- 본편 낭독문은 공백·문장부호 제외 **약 125~160자**(새 기본 기준). 참고 예시 문어 영상의 본편은 처음 168자(문장부호를 세면 181자)였는데 새 기본에서는 낭독이 42.3초에 끝나 45초에 간신히 들어가서, **2a·4a의 표현만 줄여 158자로 다시 만들었다** (사실 내용은 그대로, 영상 44.0초). 상한 근처에서는 합성할 때마다 길이가 조금씩 달라 실패할 수 있으니 여유를 두고 쓴다. 줄마다 **절을 짧게 끊어** 화면이 낭독에 맞춰 등장할 단서가 되게 한다.
- `clauses.json`에 절마다 `spoken`(소리 내어 읽는 글)과 `caption`(자막)을 따로 쓴다. 숫자와 기호는 읽는 형태로: `1973년` → `천구백칠십삼 년`, `8자` → `팔자`. 자막에는 원래 표기를 쓴다. 본편만 쓴다 (오프닝·엔딩 절은 다음 단계에서 붙는다). 예시: `reference/octopus-hearts/clauses.json`.
- 화면의 글을 낭독이 그대로 반복하지 않는다. 화면은 **그림**이 말하고, 글은 라벨 정도만.

## 4. 음성과 시각표

```bash
S=<이 스킬 폴더>/scripts            # 설치된 jarvis-knowledge-video/scripts
python "$S/setup_tts.py"            # 처음 한 번 (이미 있으면 아무것도 받지 않음). 마지막 줄 PY=…, MODEL=(Supertonic) 을 읽는다
PY=<위의 PY>; MODEL=<위의 MODEL>
"$PY" -I "$S/make_clauses.py" clauses.json clauses-full.json            # 본편 앞뒤에 찰스의 오프닝·엔딩 절을 붙인다
"$PY" -I "$S/tts_clauses.py" "$MODEL" clauses-full.json clauses     # 절마다 wav (기본: Supertonic 3 목소리 5, 속도 1.2, 톤 natural. 짧은 절은 자동으로 더 느리게, 앞뒤 무음은 잘라 냄)
"$PY" -I "$S/build_track.py" clauses-full.json clauses audio           # audio/ 에 narration.wav, timing.json(자막), clauses_timing.json(절별), parts.json(오프닝·본편·엔딩), duration.txt
```

- **목소리 (조사 → 측정 → 사용자가 듣고 고른 것):**
  - **조사:** 한국 인스타·유튜브 지식·정보 영상에서 많이 쓰는 목소리를 찾았다. 쓰는 곳은 **타입캐스트, 네이버 클로바더빙, 일레븐랩스, 캡컷·브루 앱 안의 목소리**가 주로 나온다. 타입캐스트 공식 블로그는 숏폼에서 인기 있는 목소리로 **진우(다정하고 따뜻하면서 전달이 정확한 남성), 시원(강의하듯 시원시원한 전달)**, 밝고 귀여운 **하윤**, 차분한 **연화**를 든다. **그러나 이 자료는 서비스 자신의 글이고, 목소리별 실제 사용량을 객관적으로 집계한 자료는 찾지 못했다** ("가장 많이 쓰는 목소리 1위"를 확정하지 못했다). 그 목소리들은 모두 **유료·클라우드·앱 전용**(워터마크, API 키, 약관)이라 이 패키지가 설치해 쓸 수 없고, 이 시험 환경에서는 허깅페이스와 해당 서비스 서버가 막혀 샘플도 만들지 못했다. 그래서 **오프라인으로 쓸 수 있고 한국어를 지원하는 후보**만 비교했다.
  - **평가 (직접 측정, 소리를 듣지는 못했다):** 실제 대본 19절을 합성해 **한국어 음성인식 모델(sherpa-onnx zipformer-korean)이 받아쓴 오류율(CER)**, 말 빠르기, 음높이를 쟀다. **1차:** 옛 KSS 대 Supertonic 2 → Supertonic이 같은 말 빠르기에서 오류가 절반 이하라 Supertonic 2를 기본으로 했다. **2차(사용자가 "더 자연스러운 것"을 요청):** Supertonic 3(2026-04 공개, 31개 언어)의 목소리 10개를 속도·추론 단계별로 합성해 비교하고, 같은 문장 샘플 8개(Supertonic 2 둘, Supertonic 3 여섯)를 사용자에게 보내 **사용자가 듣고 6번째 샘플(Supertonic 3 목소리 5, 속도 1.2)을 골랐다.** 그 뒤 사용자가 "속도는 조금 더 빠르게 해도 된다"고 해서 기본 속도를 1.3으로 올렸다가, 사용자가 **"찰스입니다!"의 "입니다"가 안 들린다**고 알려 와서 원인을 찾아 고쳤다 (아래 "짧은 절 처리").

| 음성·목소리 | 속도 | 초당 글자 | 받아쓰기 오류 | 평균 음높이 |
|---|---|---|---|---|
| **Supertonic 3 목소리 5 (기본)** | 1.1 / 1.2 / **1.3** / 1.35 / 1.4 | 4.6 / 5.0 / **5.4** / 5.6 / 5.8 | 14.9% / 20.8·21.7% / **21.3·22.6%** / 22.2% / 25.8·29.9% | 약 175Hz |
| Supertonic 3 목소리 6 | 1.0 / 1.1 / 1.2 / 1.3 / 1.4 | 4.3 / 4.7 / 5.1 / 5.5 / 6.0 | 16.3 / 15.8 / 19.5 / 25.3 / 29.4% | 약 180Hz |
| Supertonic 3 목소리 1 (가장 높음) | 1.1 / 1.2 / 1.3 | 4.8 / 5.3 / 5.7 | 18.1 / 22.2 / 29.4% | 약 275Hz |
| Supertonic 2 목소리 6 (이전 기본) | 1.2 / 1.4 | 5.2 / 6.1 | 11.3% / 19.0% | 약 130Hz |
| 옛 KSS (여성) | 1.0 / 1.25 | 5.6 / 6.6 | 38.5% / 38.0% | 약 280Hz |

  - 같은 속도에서 받아쓰기 오류는 **Supertonic 2가 Supertonic 3보다 낮았다** (속도 1.2: 11.3% 대 19.5%). 그래도 기본을 Supertonic 3 목소리 5로 정한 것은 **사용자가 들어 보고 고른 것**이기 때문이다 (받아쓰기 오류율은 알아듣기 쉬움이지 자연스러움이 아니다).
  - Supertonic은 합성할 때 무작위가 들어가 **같은 설정도 ±2%p 정도 흔들린다**. 표는 한 번씩 잰 값이고, 1~2%p 차이는 순위로 보지 않는다.
  - **속도:** 긴 문장만 보면 목소리 5는 1.2~1.35에서 오류가 21~23%로 거의 같고(같은 설정의 흔들림 ±2%p 안쪽) 1.4부터 26~30%로 늘어난다. 그런데 **짧은 문장은 1.3에서 무너진다** (아래). 그래서 기본은 **1.2**이고, 사용자가 "더 빠르게"라고 하면 1.3까지 올릴 수 있지만 짧은 절은 자동으로 늦춰지므로 전체가 줄어드는 시간은 예시에서 0.8초뿐이다 (아래). 목소리를 바꾸면 여유도 달라진다 (목소리 6은 1.3에서 25.3%, 목소리 1은 29.4%). 추론 단계는 5 (목소리 6에서 10단계 20.4%, 16단계 18.1%로 ±2%p 안쪽이라 올릴 이유를 찾지 못했다). 표의 "초당 글자"는 앞뒤 무음을 포함한 **클립 길이** 기준이라 실제 말 속도보다 낮다 (소리가 있는 구간만 재면 속도 1.0에서 초당 6~7음절, 1.3에서 7.5~8음절).
  - **짧은 절 처리 (사용자가 "찰스입니다!"가 깨진다고 알려 와서 찾은 것):** (1) 합성기는 짧은 문장의 **말 구간을 눌러** 끝말을 삼킨다. 속도 1.3에서 "찰스입니다!"는 "입니다"가 16번 중 2번만 들렸고(1.2에서 11번, 1.1에서 12번, **1.0에서 15번**), "찰스였습니다!"도 1.3에서 8번이었다 (모두 같은 음성인식 모델로 받아쓴 결과이고 "찰스"라는 이름은 인식기가 "철수" 같은 말로 자주 틀려 끝말만 셌다). 그래서 `tts_clauses.py`는 **글자 7개 이하의 절은 속도 1.0 이하, 8~10개는 1.1 이하**로 합성한다. (2) **느낌표가 붙으면 끝말이 더 자주 삼켜졌다** ("찰스입니다!" 속도 1.0에서 25/32, 마침표로 바꾸면 32/32). 자막은 사용자의 문구 그대로 "!"를 두고 오프닝 낭독문(`spoken`)만 "찰스입니다."로 했다 (`reference/charles/opening.json`). 엔딩 "찰스였습니다!"는 속도 1.0에서 느낌표여도 32/32라 그대로 둔다. (3) 합성된 클립 **앞 0.3~0.6초·뒤 0.2~0.6초가 무음**이었는데 `build_track.py`가 그대로 이어 붙이고 있었다. 앞 0.08초·뒤 0.15초만 남기고 자르게 해 (소리 구간은 그대로, 받아쓰기 오류도 늘지 않았다: 전체 19절 오류 글자 48 → 42) 줄 사이 빈 시간과 자막 시작·끝이 실제 낭독에 맞는다. 결과: 같은 대본이 이전 방식 1.2에서 낭독 50.2초 → **42.3초**, 이전 방식 1.3에서 46.8초 → 새 방식 1.3에서 42.1초. 새 파이프라인 전체를 24번 반복하니 "찰스입니다."의 끝말이 24번 모두(22번은 "입니다", 2번은 "임이다·임미다"로 받아쓰임), "찰스였습니다!"는 24번 모두 들렸다. 단 **음성인식이 들은 것이지 사람 귀로 확인한 것이 아니다.**
  - **다른 목소리:** `tts_clauses.py … 1.2 natural <번호>`로 바꾼다. 번호는 측정한 음높이로 구분했다 (0·1·3 높은 목소리, 2·4 중간, 5·6 중간~낮음, 7·8·9 낮은 목소리. 자세한 표는 `tts_clauses.py` 머리말). **성별은 소리로 확인하지 못했다.**
  - **톤 후처리(`bright`/`cheer`)는 Supertonic에서는 기본으로 쓰지 않는다.** Supertonic 2 목소리 6에서 `bright`(+2반음, 고음 강조)가 오류를 20.8% → 28.1%로 늘렸다 (Supertonic 3에서는 재 보지 않았다). 그래도 원하면 `tts_clauses.py … 1.2 bright 5`.
  - **이 수치는 음성인식 모델의 받아쓰기이지 사람의 귀가 아니다.** "듣기 좋은지, 명랑한지, 이름·오리 캐릭터와 어울리는지"는 사용자가 들어 보고 정한다. 사용자가 "목소리 바꿔 줘"라고 하면 번호·속도·톤을 바꿔 음성부터 다시 만들고 샘플을 보낸다. 옛 목소리는 `setup_tts.py --with-kss`로 받은 `KSS_MODEL`로 만들 수 있다.
  - **더 자연스러운 목소리가 필요하면** 타입캐스트·클로바·마이크로소프트 신경망 목소리 같은 클라우드 음성이 오프라인 모델보다 자연스럽다고 알려져 있다 (이 환경에서는 비교하지 못했다). 쓰려면 계정이나 API 키가 필요하고 **영상 대본이 외부 서비스로 전송**되므로 사용자 동의가 먼저다. 이 스킬은 아직 그 연결을 갖고 있지 않다.
  - 이 음성은 숫자·영어·약어를 낭독문에 **읽는 형태로 쓰지 않으면** 틀리게 읽을 수 있다 (예: "삼십 초", "팔자"). 자막 글(`caption`)에는 숫자를 써도 된다.
- `build_track.py`가 영상 길이(35~45초)를 정해 `duration.txt`에 쓴다. 마지막 장면을 2초 이상 보여 주려고 낭독이 끝난 뒤 2초를 더한다. **낭독이 43초를 넘어 실패하면** 본편 대본을 줄인다 (속도를 올리는 것은 권하지 않는다: Supertonic 3은 1.3부터 짧은 절이 뭉개진다). 줄 사이 간격은 기본 0.4초, 같은 줄 안은 0.14초다 (여기에 클립마다 남긴 무음 0.08+0.15초가 더해져 실제 빈 시간은 줄 사이 약 0.63초, 같은 줄 안 약 0.37초).
- 나레이션은 **`loudnorm`으로 −16 LUFS**에 맞춰진다. 영상에 넣을 때는 `data-volume="0.85"`.

## 5. 화면 만들기 (HyperFrames)

```bash
export HYPERFRAMES_NO_TELEMETRY=1 DO_NOT_TRACK=1
node "<PLUGIN_ROOT>/skills/hyperframes/scripts/plugin-cli.mjs" init <slug> --skip-skills --non-interactive
"$PY" -I "$S/prepare_assets.py" <slug>      # gsap.min.js(로컬), Pretendard woff2 3종 (CDN 쓰지 않음)
cp audio/narration.wav audio/timing.json audio/clauses_timing.json audio/parts.json audio/duration.txt <slug>/assets/
```

`<PLUGIN_ROOT>`는 `jarvis-hyperframes` 스킬의 방식으로 찾는다. 그다음 참고 예시의 구조를 가져와 이 주제의 장면을 만든다 (그대로 복사하지 않는다).
- `reference/bee-dance/build_video.py`: 장면을 갈아 끼우는 구성(꿀벌이 장면 사이를 이어 감), 길 따라 움직이기, 점선 그리기.
- `reference/octopus-hearts/build_video.py`: **찰스 오프닝·엔딩이 붙은 완성형.** 한 장면이 15초 동안 하나의 도표를 키우는 구성(문어 몸속에 장기가 하나씩 등장), 피 알갱이 흐름(`offset-path`), 심장 박동 함수(`beats`), 장면 3개. **본편 장면은 본편 시각(전체 시각에서 `OFF`를 뺀 값)으로 쓰고 호스트 `data-start`에만 `OFF`를 더한다** (오프닝 길이가 바뀌어도 장면 코드를 안 고친다). `charles.write_scenes(proj, 절별 시각, narration.wav, 전체 길이, OFF)`가 오프닝·엔딩 호스트를 돌려준다.
- `reference/bee-dance/`는 오프닝·엔딩 도입 **전**의 예시다 (장면 구성과 기법만 참고).

**구성:** 배경(`bg`) + 칩(주제 이름, 상단 좌측) + **장면 3~5개** + 자막(`captions`) + 오디오 1개. 장면은 `compositions/<이름>.html` 하위 구성으로, 호스트 id = 장면 root의 `data-composition-id` = 타임라인 키가 같아야 한다.

**연출 규칙**
- **목소리가 시계다.** 각 요소는 `clauses_timing.json`의 절 시작 시각(본편 시각 = 전체 시각 − `OFF`)에 맞춰 등장한다. 한 장면의 모든 것이 처음에 다 나와 있으면 슬라이드가 된다.
- **하나의 도표가 자란다.** 가장 단순한 그림에서 시작해 낭독이 부분을 말할 때마다 하나씩 더한다. 장면이 바뀌어도 같은 물체를 이어서 쓴다(꿀벌: 벌이 장면 1에서 3까지 그대로 춤을 춘다).
- 색: 어두운 바탕 + 주제 색 1개(꿀벌: 꿀색 `#F6B21A`) + 크림색 글자. 글꼴 Pretendard(800/700/400). **글자는 28px 이상**, 자막은 56px 700, 하단 `top: 884px`.
- 마지막 한 줄(핵심 요약)은 낭독이 끝나기 전에 띄워 **2초 이상 유지**한다. 브랜드 끝 카드는 없다.
- 장면 전환: 다음 장면을 0.3초 겹쳐 시작하고 앞 장면은 불투명도·블러로 사라진다. 같은 요소는 같은 위치에서 이어 받는다.
- 본편의 그림은 **코드로 그린다**(SVG/CSS). 외부 이미지, 로고, 상표 캐릭터, 실존 인물 사진은 쓰지 않는다 (예외: 사용자가 만든 찰스 그림 `assets/charles/`).

**기술 규칙 (시험하며 확인한 것)**
- 장면 안에서는 `fromTo`를 쓴다. 같은 대상에 `fromTo`를 여러 번 쓰면 `immediateRender: false`를 주고, 쉬는 상태는 `tl.set(..., 0)`으로 만든다 (아니면 마지막 `from` 값이 처음부터 적용된다).
- 점선을 그려 넣을 때는 **마스크 경로**를 쓴다(점선 자체의 `strokeDashoffset`을 움직이면 점이 흘러갈 뿐이다). 실선은 `pathLength="100" stroke-dasharray="100 120"`, `strokeDashoffset 100→0` (간격이 길이보다 길어야 둥근 끝점이 안 보인다).
- 길을 따라 움직이는 물체는 CSS `offset-path: path(...)` + `offsetDistance` 트윈. 몸을 흔들거나 날갯짓은 `repeat`를 **유한 횟수**로(`repeat: -1` 금지). `onUpdate` 같은 콜백으로 화면을 바꾸지 않는다.
- **위치를 정하지 않은 `position:absolute` 0×0 요소는 화면 왼쪽 위(0,0)에 남아 작은 점으로 보인다** (일시정지 표시가 그랬다). 움직이는 물체 안의 부품(심장, 표시)은 그 물체의 자식으로 넣어서 함께 움직이게 한다.
- 파이썬 문자열 서식(`%`)과 CSS의 `%`(`offset-distance: 0%`)가 충돌한다. 자리표시자는 `__이름__` + `.replace()`로.
- 렌더 때 **CDN을 쓰지 않는다** (GSAP는 `assets/gsap.min.js`). 글꼴은 각 장면 파일 안에서 `@font-face`.
- 장면 겹침, 자막 위치, 좌표 계산은 `snapshot`으로 눈으로 확인하고 고친다.

## 6. 점검과 렌더 (이 순서)

```bash
node "<PLUGIN_ROOT>/skills/hyperframes/scripts/plugin-cli.mjs" check --json > check.json
"$PY" -I "$S/check_summary.py" check.json        # 오류 0 이어야 한다. 경고·정보는 검토
node "<PLUGIN_ROOT>/skills/hyperframes/scripts/plugin-cli.mjs" snapshot --at <t1,t2,…>   # 장면마다 2~3개 시점을 직접 본다
node "<PLUGIN_ROOT>/skills/hyperframes/scripts/plugin-cli.mjs" render
"$PY" -I "$S/verify_video.py" renders/<파일>.mp4 assets/timing.json
```

- `snapshot`에서 **글이 겹치거나 잘리거나 어긋난 것, 장면 전환의 튐**을 찾아 고친 뒤 렌더한다. 렌더는 몇 분 걸린다(30초 영상이 GPU 없는 환경에서 약 4분).
- `verify_video.py`가 불합격이면 보고하기 전에 고친다 (소리 크기가 −13 LUFS보다 크면 `data-volume`을 낮추고 다시 렌더하거나 오디오만 다시 묶는다).
- **소리는 들을 수 없다.** 측정한 것(길이, 크기, 절마다 소리 있음)과 듣지 못한 것(발음, 억양)을 구분해서 보고한다.

## 지켜야 할 것

- **오프닝·엔딩 문구와 찰스의 모습은 사용자가 정한 것이다.** 바꾸지 않는다. 바꾸고 싶으면 사용자에게 제안하고 `reference/charles/*.json`과 `assets/charles/`를 함께 고친다.
- 사실은 확실한 것만. 확인 못 한 것을 그럴듯하게 쓰지 않는다.
- 동의 없이 외부 서비스(HeyGen, MaxFusion, 온라인 음성 합성 등)를 쓰지 않는다. 텔레메트리를 켜지 않고, 피드백 전송·`publish`·`auth login`을 하지 않는다.
- `~/.jarvis-knowledge-video`와 `knowledge-videos/` 밖의 파일을 고치지 않는다. 기존 영상·프로젝트를 덮어쓰지 않는다 (같은 이름이면 `-2`를 붙인다).
- 다른 사람의 목소리를 흉내 내지 않는다. 음성은 이 스킬의 로컬 모델만.
- 최종 렌더 전에 `check` 오류 0과 `snapshot` 확인을 마친다.

## 막힐 때

| 증상 | 해결 |
|---|---|
| `setup_tts.py`가 모델 SHA-256 불일치로 중단 | 릴리스 파일이 바뀐 것. 내용을 확인하고 사용자 승인 후 해시를 갱신 |
| 음성이 비어 있다 / `no frontend available` | 옛 KSS 음성에서 sherpa-onnx가 1.13.8이 아닌 경우(2.0.0은 실패). `setup_tts.py`를 다시 실행. Supertonic은 1.13.8의 `OfflineTtsSupertonicModelConfig`를 쓴다 |
| `build_track.py`가 "낭독이 N초" 로 실패 | 본편 대본을 줄인다 (125~160자) |
| 렌더가 `sub_timeline_script_failure` | GSAP가 CDN을 쓰고 있다. `assets/gsap.min.js`로 |
| 자막이 서로 겹침 | 절 사이 간격(`--intra`, `--inter`)을 늘리거나 자막 클립 길이를 줄인다 |
| `ffmpeg`/`npm`이 없다 | 사용자에게 알려 설치하게 한다 (윈도우: `winget install Gyan.FFmpeg`) |

시험한 범위: 리눅스에서 `setup_tts.py`(빈 홈에서 가상환경·패키지 설치, Supertonic 3 내려받기와 SHA-256 확인, 안전한 압축 풀기), 음성 합성(Supertonic 3 목소리 10개, Supertonic 2 일부, 옛 KSS), 한국어 음성인식으로 받아쓰기 오류 측정, **새 기본(목소리 5, 속도 1.2, 짧은 절 규칙, 앞뒤 무음 제거)으로 `make_clauses.py`→`tts_clauses.py`→`build_track.py`를 본편 115자(전체 36초)·135자(39초)·149자(41초)·168자(45초)에 실행하고 "찰스입니다."·"찰스였습니다!"의 끝말을 24번씩 반복해 받아쓰기로 확인**, `build_track.py`(35~45초 자동 결정, 자막 합치기, 오프닝·본편·엔딩 구간), `make_clauses.py`, `prepare_assets.py`, 꿀벌 영상(30초)과 **찰스(사용자가 만든 오리 박사 그림) 오프닝·엔딩이 붙은 「문어의 심장은 세 개」를 이전 기본(Supertonic 2 목소리 6, 속도 1.4, 45.0초)과 새 기본(Supertonic 3 목소리 5, 속도 1.2, 짧은 절 감속, 무음 제거, 본편 158자, 44.0초)으로 각각** 처음부터 끝까지 만들어 `check` 오류 0·경고 0, `snapshot`과 렌더한 MP4의 프레임 눈 확인, `verify_video.py` 전부 합격(새 판: −15.0 LUFS, 피크 −2.8 dBFS, 자막 단위 모두 소리 있음, 렌더한 MP4의 소리 트랙만 따로 받아쓰게 해도 "찰스입니다."·"찰스였습니다."가 나옴). 새 판은 **절마다 6번 합성해 음성인식이 가장 잘 받아쓴 것을 골라** 만들었다 (오류 글자 39 → 19. 이 선택 도구는 음성인식 모델을 따로 받아야 해서 패키지에 넣지 않았다). 톤 후처리는 `rubberband`가 있는/없는 ffmpeg(KSS 음성)와 Supertonic(rubberband 경로)에서 실행했다. 시험하지 못한 범위: **윈도우**, 음성의 발음·억양·**듣기 좋은지**(소리를 들을 수 없어 받아쓰기 오류율 같은 측정으로만 비교), 말할 때 몸의 움직임이 소리와 맞는지(캡처한 프레임으로만 확인), 음성 모델 가중치(OpenRAIL-M) 라이선스 원문(이 환경에서 열지 못함), 한국 크리에이터가 실제로 가장 많이 쓰는 목소리의 객관적 순위(자료 없음), 웹 검색 원문 페이지 직접 열람.
